1. BACKEND DEPLOYMENT OVERVIEW
--------------------------------------------------------------------------------
This document outlines production deployment strategies for the backend REST API 
service (/server). The backend is built with Express.js, Prisma ORM, JWT authentication, 
Multer file storage, and Node Cron schedulers.

Local development servers are NOT required for cloud production deployments.


2. REQUIRED PRODUCTION ENVIRONMENT VARIABLES
--------------------------------------------------------------------------------
When deploying the backend to a cloud hosting platform (e.g. Render, Railway, 
AWS, Heroku), configure the following environment variables in your cloud console:

  PORT=5000 (or provided dynamically by cloud host)
  DATABASE_URL="file:./dev.db" (or MySQL/PostgreSQL connection string)
  JWT_SECRET="your_production_secure_jwt_secret_key_2026"
  JWT_EXPIRES_IN="24h"
  NODE_ENV="production"
  UPLOAD_DIR="./uploads"
  FRONTEND_URL="https://your-frontend-domain.com"


3. DEPLOYMENT OPTION 1: RENDER (RECOMMENDED PAAS)
--------------------------------------------------------------------------------
Render provides free/low-cost Node.js hosting with automated Git deployment.

Step 1: Push Project to GitHub
  Ensure your project is pushed to your GitHub repository:
  https://github.com/Gunjan-Kosta/meeting-management

Step 2: Create a New Web Service on Render
  1. Log into Render (https://render.com) and click 'New +' -> 'Web Service'.
  2. Connect your GitHub repository meeting-management.
  3. Configure the service parameters:
       - Name: meeting-management-backend
       - Root Directory: server
       - Environment: Node
       - Build Command: npm install && npx prisma db push && node seed.js
       - Start Command: npm start
  4. Add Environment Variables:
       - JWT_SECRET: (Set a strong secret key)
       - JWT_EXPIRES_IN: 24h
       - NODE_ENV: production
       - DATABASE_URL: file:./dev.db
  5. Click 'Create Web Service'. Render will build and deploy your backend API.


4. DEPLOYMENT OPTION 2: RAILWAY.APP
--------------------------------------------------------------------------------
Step 1: Log into Railway (https://railway.app) and create a New Project.
Step 2: Select 'Deploy from GitHub repo' and pick meeting-management.
Step 3: Set Root Directory to /server.
Step 4: Set Build Command: npm install && npx prisma db push && node seed.js
Step 5: Set Start Command: npm start
Step 6: Under Variables, set JWT_SECRET, NODE_ENV=production, and PORT.
Step 7: Generate Domain to get your live backend URL (e.g. https://xxx.up.railway.app).


5. DEPLOYMENT OPTION 3: LINUX VPS (AWS EC2 / DIGITALOCEAN / LINODE)
--------------------------------------------------------------------------------
For dedicated server control using Ubuntu, PM2, and Nginx reverse proxy:

Step 1: Connect to your server via SSH:
  ssh ubuntu@your-server-ip

Step 2: Install Node.js (v18+) and PM2:
  curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash -
  sudo apt-get install -y nodejs git nginx
  sudo npm install -g pm2

Step 3: Clone Repository & Setup Server Directory:
  git clone https://github.com/Gunjan-Kosta/meeting-management.git
  cd meeting-management/server
  npm install
  npx prisma db push
  node seed.js

Step 4: Start Backend with PM2 Process Manager:
  pm2 start app.js --name meeting-backend
  pm2 save
  pm2 startup

Step 5: Configure Nginx Reverse Proxy:
  Create /etc/nginx/sites-available/meeting-backend:

  server {
      listen 80;
      server_name api.yourdomain.com;

      location / {
          proxy_pass http://127.0.0.1:5000;
          proxy_http_version 1.1;
          proxy_set_header Upgrade $http_upgrade;
          proxy_set_header Connection 'upgrade';
          proxy_set_header Host $host;
          proxy_cache_bypass $http_upgrade;
      }
  }

  Enable site and restart Nginx:
  sudo ln -s /etc/nginx/sites-available/meeting-backend /etc/nginx/sites-enabled/
  sudo nginx -t
  sudo systemctl restart nginx


6. DEPLOYMENT OPTION 4: DOCKER CONTAINER
--------------------------------------------------------------------------------
Create a Dockerfile inside the server/ directory:

  FROM node:18-alpine
  WORKDIR /app
  COPY package*.json ./
  RUN npm install
  COPY . .
  RUN npx prisma generate
  RUN npx prisma db push
  EXPOSE 5000
  CMD ["npm", "start"]

Build & Run Docker Container:
  docker build -t meeting-backend ./server
  docker run -d -p 5000:5000 --name meeting-api meeting-backend


7. POST-DEPLOYMENT VERIFICATION
--------------------------------------------------------------------------------
Once deployed, test your live cloud API healthcheck endpoint:
  GET https://<your-deployed-backend-url>/api/health

Expected Response:
  {"status":"HEALTHY","system":"Enterprise Meeting Management System","timestamp":"..."}


8. CONNECTING FRONTEND TO DEPLOYED BACKEND
--------------------------------------------------------------------------------
After deploying your backend, update the frontend configuration in client/src/services/api.js:

  const API = axios.create({
    baseURL: 'https://<your-deployed-backend-url>/api',
  });

Deploy your /client directory to Vercel, Netlify, or Cloudflare Pages.
